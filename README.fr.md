## Prérequis

- [Node.js](https://nodejs.org/) 18+
- [Claude Code](https://github.com/anthropics/claude-code) installé en global
- **Windows** 10 ou 11
- **macOS** 12+ (Intel ou Apple Silicon)
- **Linux** Ubuntu 22.04+, Fedora 38+ ou équivalent
  - L'AppImage nécessite `libfuse2` sur Ubuntu 24.04+ : `sudo apt install libfuse2`
  - Le stockage du token GitHub nécessite `libsecret` : `sudo apt install libsecret-1-dev gnome-keyring`

## Installation

Téléchargez le dernier installeur depuis les [Releases](https://github.com/Sterll/claude-terminal/releases).

> [!IMPORTANT]
> **Utilisateurs macOS :** si vous voyez *« Claude Terminal est endommagé et ne peut pas être ouvert »*, lancez ceci dans le Terminal :
> ```bash
> xattr -cr /Applications/Claude\ Terminal.app
> ```
> C'est nécessaire parce que l'application n'est pas encore signée. Sinon, clic droit sur l'app → Ouvrir.

Ou compilez depuis les sources :

```bash
git clone https://github.com/Sterll/claude-terminal.git
cd claude-terminal
npm install
```

## Fonctionnalités

### Interface de chat (Claude Agent SDK)
- Interface de chat intégrée propulsée par le Claude Agent SDK, avec réponses en streaming
- **Rendu markdown enrichi** : diagrammes mermaid, formules KaTeX, code coloré syntaxiquement, arborescences de fichiers, tableaux kanban, blocs de diff, aperçus HTML, et plus
- **Cartes de permission** : Autoriser, Toujours autoriser ou Refuser les demandes d'outils ; quand c'est une de vos propres règles `permissions.ask` qui déclenche la demande, la carte nomme cette règle et masque « Toujours autoriser » pour qu'on ne puisse pas la contourner d'un clic
- **Mode plan** : relire et approuver ou rejeter les plans de l'agent avant exécution
- **Blocs de réflexion** : sections dépliables montrant le raisonnement de Claude
- **Cartes d'outils** : cartes repliables détaillant l'exécution des outils, avec rafraîchissement des outils MCP, envoi de feedback et propositions de skills
- **Visualisation des sous-agents** : suivi imbriqué des tâches déléguées ; le résumé de chaque sous-agent indique sa branche de worktree git et tout changement de modèle en cours de route
- **Widget de todos** : liste de tâches persistante au-dessus de la saisie, qui disparaît d'elle-même une fois terminée
- **Pièces jointes** : coller, glisser-déposer ou choisir des images PNG/JPEG/GIF/WebP (jusqu'à 20 Mo), ainsi que des fichiers texte et des PDF
- **Commandes slash** : autocomplétion des commandes (/compact, /clear, /help, skills personnalisés)
- **Mentions @ en ligne** : le champ de saisie enrichi permet de taper des mentions @ sans quitter la zone de rédaction
- **Rewind de fichiers** : revenir à un état antérieur des fichiers via le checkpointing du SDK, pratique pour annuler des modifications indésirables en cours de session
- **Suivi des coûts** : nom du modèle, nombre de tokens et coût en USD dans la barre de statut
- **Fenêtre de contexte de 1M** : contexte étendu pour les grandes bases de code (mode API uniquement)
- **Changement dynamique de modèle et d'effort** : le sélecteur de modèle est construit en direct depuis le catalogue du CLI Claude, donc les nouveaux modèles (Fable 5.1 par exemple) apparaissent automatiquement ; changez de modèle et de niveau d'effort (low, medium, high, xhigh) en cours de conversation sans repartir de zéro
- **Modèle, effort et mode de permission par conversation** : chaque onglet garde ses propres réglages, un choix dans une conversation ne déborde jamais sur la suivante. Les valeurs enregistrées ne sont que les défauts d'un nouvel onglet, modifiables via l'entrée « Utiliser pour les nouvelles conversations » de chaque menu
- **Modes de permission** : basculer entre défaut, accepter les modifications, plan et contourner les permissions depuis le composeur, en cours de session
- **Palier premium** : les modèles de la famille Fable sont signalés en violet avec un badge « Premium », une étiquette sur l'onglet et un avis quand un nouvel onglet en hérite, parce que cette famille consomme sa propre limite d'usage
- **Tiroir des tâches de fond** : un tiroir repliable, propre à la session courante, montre ce que Claude exécute en arrière-plan pour que vous puissiez continuer à discuter
- **Bibliothèque d'artefacts et onglet Documents** : les fichiers et extraits générés par Claude sont enregistrés dans une bibliothèque réutilisable et apparaissent aussi dans un onglet Documents propre à la conversation, avec un panneau Artefacts dédié listant tout ce qui est publié pour le projet
- **Recherche dans la conversation** : Ctrl+F pour chercher dans la transcription en cours
- **Épingler des conversations** : garder les sessions importantes en haut de la liste
- **Forker une session** : repartir de n'importe quel message pour explorer une autre piste ; Claude Terminal prévient au lieu de jeter un tour en file d'attente
- **Suggestions de suite** : des puces de suggestion contextuelles apparaissent après la réponse de Claude pour guider la conversation
- **Récapitulatifs de session** : résumés générés automatiquement pour les sessions terminées
- Tapez @project pour joindre le README.md et l'arborescence de n'importe quel projet comme contexte
- Tapez **@tab** pour partager votre session de terminal courante, ou **@conversation** pour référencer un autre fil de discussion
- Tapez **@context** pour injecter un pack de contexte, ou **@prompt** pour insérer un modèle de prompt enregistré
- **Amélioration du prompt** : réécriture IA de votre message en un clic via Haiku, pour des instructions plus claires avant l'envoi
- Interruption du streaming en plein tour, noms d'onglets générés automatiquement par le modèle haiku
- Indicateur de compaction affiché pendant la compression du contexte, pour savoir quand ça se produit

### Terminaux
- Plusieurs terminaux Claude Code par projet, avec interface à onglets
- Rendu accéléré par GPU via xterm.js + WebGL (repli DOM)
- Bascule entre mode terminal et mode chat pour chaque onglet
- Réorganisation des onglets par glisser-déposer, renommage, notifications bureau
- Filtrage des terminaux par projet
- Détection adaptative de disponibilité avec indicateur de statut
- Capture de la sortie du terminal, pour que les outils de lecture et les outils MCP renvoient réellement ce qui s'est exécuté

### Navigation
- Choisissez votre façon de parcourir les projets : une barre d'onglets en haut, ou la colonne de projets classique sur le côté
- Demandé une fois dans l'assistant de premier lancement, modifiable à tout moment depuis les Paramètres

### Fichiers
- Un écran Fichiers dédié montre chaque fichier touché dans une session, avec des diffs par session rendus à la manière de GitHub
- Relisez rapidement ce que Claude a changé sans quitter le contexte du chat
- Ou gardez l'arborescence du projet ancrée à côté de la conversation, comme avant l'écran Fichiers

### Comptes
- Associez un compte Claude distinct à chaque projet, avec son propre magasin d'identifiants isolé
- Changez de projet sans changer de compte à la main, et sans que la connexion d'un projet affecte celle d'un autre
- Usage par compte affiché dans les Paramètres, et bascule en cas de limite atteinte qui poursuit la conversation

### Claude Remote Control (claude.ai et mobile)
- Placez une session de chat sur [claude.ai/code](https://claude.ai/code) et l'application mobile Claude, pour la suivre ou la piloter depuis votre téléphone
- Décidé **par conversation**, jamais globalement : une session rejoint quand vous le demandez dans cet onglet, via le bouton du pied de page ou la commande `/remote-control`
- Miroir en lecture seule ou pilotage complet, au choix ; prompts, interruptions et réponses aux permissions repassent tous par le bureau
- `--rc` optionnel dans les onglets terminal pour que les sessions CLI rejoignent aussi
- Un onglet **Connectivité → claude.ai** liste chaque conversation partagée avec un retour vers l'onglet correspondant
- Respecte le coupe-circuit `disableRemoteControl` des réglages managés de Claude Code, pour qu'une politique d'organisation ne puisse pas être levée depuis l'application

### Claude dans Chrome
- Laissez les sessions de chat piloter votre navigateur via l'extension Chrome de Claude
- Ajoute le serveur MCP `claude-in-chrome` et ses 22 outils navigateur à la session
- Opt-in, et il adopte l'hôte de messagerie native existant de Claude Code au lieu de l'écraser

### Voix
- Dictez vos messages au chat au micro (transcription Groq)
- Mode dictée verbatim avec routage vers l'onglet actif, pour que vos mots atterrissent dans la bonne conversation
- Profil de session mains libres pour des sessions entièrement vocales
- Prononce les noms de projets comme vous les diriez, pour que les mentions @ à la voix se résolvent correctement

### Gestion de projets
- Organisez vos projets en dossiers imbriqués avec glisser-déposer
- Personnalisez chaque projet avec des couleurs et des icônes emoji
- Barre d'actions rapides : commandes en un clic configurables par projet (build, test, deploy, scripts personnalisés...)
- Explorateur de fichiers intégré avec vue arborescente, sélection multiple, recherche, indicateurs git et renommage en ligne ; clic droit sur un fichier pour le joindre comme contexte au chat courant
- Système modulaire de types de projet (standard, FiveM, webapp, Python, API, Minecraft, bot Discord)
- Fenêtre de réglages par projet

### Intégration Git
- **Branches** : basculer, créer, supprimer, avec vue arborescente des branches locales et distantes
- **Synchronisation** : pull (rebase), push, merge avec détection et résolution des conflits
- **Panneau des modifications** : voir les fichiers indexés, non indexés et non suivis, indexer/désindexer et committer
- **Historique des commits** : graphe de commits façon IntelliJ en SVG, filtrage par branche et par auteur, défilement infini
- **Cherry-pick et revert** : opérations avancées depuis l'historique
- **Gestion des worktrees** : créer, basculer et supprimer des worktrees git, avec badge de bascule rapide dans la barre d'outils
- **Gestion des stashes** : sauvegarder, appliquer, dépiler et inspecter
- **Recherche dans l'historique** : recherche plein texte dans l'historique des commits
- **Abandon des modifications** : jeter rapidement les modifications non indexées, fichier par fichier
- **Amend** : modifier le message ou le contenu du dernier commit avant de pousser
- **Messages de commit par IA** : génération automatique de messages conventionnels via l'API GitHub Models
- **Pull requests** : créer et consulter des PR directement depuis l'application

### Intégration GitHub
- Authentification OAuth Device Flow (sécurisée, sans copier-coller de token)
- **Support GitHub Enterprise** : connexion à des instances GitHub Enterprise auto-hébergées
- **Recherche de dépôts dans l'assistant de clonage** : chercher un dépôt GitHub par nom sans quitter l'application
- **Pastille de statut CI/CD** : statut en direct du dernier run affiché dans la barre d'en-tête du terminal, avec un bouton pour sauter directement à l'étape en échec
- Consultation des runs CI/CD par dépôt
- Consulter, créer et relire des pull requests depuis l'application ; support multi-forge (GitHub, GitLab)
- Token stocké de façon sécurisée via keytar (Gestionnaire d'identifiants Windows, Trousseau macOS, libsecret sous Linux)

### Tour de contrôle
- Vue temps réel de tous les agents Claude actifs, tous projets confondus
- Voyez ce que fait chaque agent (outils en cours, statut, dernière activité)
- Vue grille : une carte par session ouverte, groupée par projet, avec miniatures de terminal en direct, badge de modèle et boutons de nouvelle session par projet
- Filtres et tri : par projet, par statut, recherche texte, classés par votre dernière interaction
- Vue focus : agrandir une session dans le panneau, avec une pellicule des autres sessions du projet, des titres de session éditables et un saut en un clic vers la vue Claude
- Les sessions terminées restent mises en évidence jusqu'à ce que vous les ayez vues, pour que rien ne passe à la trappe
- Interrompre n'importe quelle session en cours directement depuis le panneau
- Répondre aux invites AskUserQuestion sans basculer vers l'onglet de chat
- Outils MCP pour la supervision des agents et l'interruption à distance

### Tâches parallèles
- Décomposez une fonctionnalité en sous-tâches parallèles et exécutez-les simultanément comme autant d'agents Claude
- Chaque tâche tourne dans son propre worktree git et sa propre branche, ce qui isole le travail
- Le mode auto laisse Claude décider du nombre optimal de tâches parallèles
- Cartes de tâches repliables avec visualiseur de diff et accès terminal par tâche
- Agent de fusion automatique : Claude relit et fusionne les branches terminées dans votre branche principale
- État complet de l'exécution persisté sur disque et restauré au redémarrage

### Rejeu de session
- Parcourez vos anciennes sessions Claude Code et rejouez-les pas à pas
- La vue chronologique montre tous les prompts, appels d'outils et réponses dans l'ordre
- Curseur façon lecteur vidéo pour sauter à n'importe quel moment de la session
- Des cartes Q&R mettent en avant les échanges question-réponse pour une relecture facile

### Tableau de bord
- Trois sous-vues : **Vue d'ensemble**, **Kanban** et **Chronologie**
- Vue d'ensemble : branche courante, commits en avance/retard, commits récents, contributeurs
- Statistiques de code : lignes par langage, nombre de fichiers, nombre de commits
- Nombre de terminaux actifs
- Suivi de l'usage de l'API Claude avec rafraîchissement automatique
- **Chronologie du projet** : tous les enregistrements que l'application conserve déjà, fusionnés en une seule vue chronologique — commits, sessions Claude, temps suivi, exécutions de workflows, exécutions parallèles et artefacts — filtrable par période et par type, pour que « qu'est-il arrivé à ce projet » tienne sur un écran au lieu de six

### Suivi du temps
- Détection automatique des sessions par projet (inactivité de 15 min, détection veille/réveil)
- Stockage léger séparé (`timetracking.json`) avec archives mensuelles
- Vue par période : aujourd'hui, cette semaine, ce mois, plage personnalisée
- Statistiques : moyenne quotidienne, plus longue série, graphiques d'évolution, sessions récentes
- Bascule à minuit et points de contrôle périodiques

### Hooks
- S'intègre aux hooks du CLI Claude Code pour un suivi d'activité en temps réel
- Installation en un clic dans `~/.claude/settings.json` (non destructive, préserve vos hooks)
- Types de hooks : PreToolUse, PostToolUse, Notification, SessionStart, Stop, DirectoryAdded (déclenché par `/add-dir`), et d'autres
- Bus d'événements avec des événements normalisés pour le suivi des sessions, des outils et des sous-agents
- Repli sur la lecture de la sortie du terminal quand les hooks ne sont pas disponibles

### Plugins
- Parcourir et découvrir des plugins depuis les marketplaces configurées
- Installer des plugins directement depuis l'application (via le CLI Claude)
- Ajouter des marketplaces communautaires par URL GitHub
- Filtrage par catégorie et recherche
- Consulter les détails et le README d'un plugin

### Marketplace de skills
- Chercher et parcourir les skills disponibles
- Installation et désinstallation en un clic
- **Vérification des mises à jour** : voir quels skills et plugins installés ont une nouvelle version
- Consulter le README et les détails d'un skill
- Cache local pour une navigation rapide

### Bibliothèque
- Gérez des **packs de contexte** réutilisables (documents, extraits, contenus de fichiers) et des **modèles de prompt**
- Injectez packs de contexte et modèles de prompt directement dans le chat via les mentions @context et @prompt
- Insérez un modèle de prompt dans n'importe quel terminal en un clic depuis la barre d'outils
- Générez des skills et des agents en arrière-plan avec l'Agent SDK

### Skills et agents
- Parcourir et gérer les skills et agents Claude Code
- Consulter les fichiers SKILL.md et les configurations d'agents
- **Éditeur avec coloration syntaxique** : éditez les fichiers de skills et d'agents avec numéros de ligne et coloration complète via highlight.js
- Chargement des skills depuis `~/.claude/skills`, les plugins et les ressources embarquées

### Serveurs MCP
- Configurer, démarrer et arrêter des serveurs MCP
- Configuration des variables d'environnement
- **Registre MCP** : parcourir et chercher dans le registre public des serveurs MCP

### Sessions
- Consulter les sessions Claude Code par projet
- Parcourir l'historique des sessions avec horodatages et métadonnées
- Épingler des sessions en haut et les renommer en ligne depuis la boîte de reprise
- Modale de reprise de session modernisée, avec recherche et sessions épinglées
- Les sessions affichent le vrai titre de la conversation au lieu d'un horodatage, et sont cherchables par identifiant
- **Déplacer une session vers un autre projet** : relocaliser une conversation sans perdre son historique
- Les noms d'onglets personnalisés sont verrouillés et ne sont plus écrasés silencieusement par le nommage automatique

### Mémoire et connaissance globale
- Éditez les fichiers CLAUDE.md globaux, de réglages et propres au projet
- Insertion de modèles pour les motifs courants
- **Connaissance globale** : un magasin de faits, conventions et préférences valables pour tous les projets, une entrée markdown chacun, disponible dans chaque session
- Épinglez, activez/désactivez et cherchez dans les entrées ; les entrées activées sont synchronisées dans un bloc balisé de `~/.claude/CLAUDE.md`, avec un aperçu du bloc avant écriture
- Outils MCP (`knowledge_list`, `knowledge_write`, `knowledge_search`...) pour que Claude puisse les lire et les écrire lui-même

### Kanban
- Un tableau kanban par projet, avec colonnes personnalisées, glisser-déposer entre elles et archivage
- Niveaux de priorité, dates d'échéance, étiquettes et assignations sur les cartes
- Filtrage, recherche et statistiques par colonne
- Jeu complet d'outils MCP pour que Claude crée et déplace des cartes pendant qu'il travaille, plus un nœud de workflow `kanban_create_card`


L'installeur est généré dans le répertoire `build/`.

## Tests

```bash
# Lancer la suite de tests (149 suites Jest, jsdom)
npm test

# Tests en mode watch pendant le développement
npm run test:watch

# ESLint sur main, renderer, shared, serveurs MCP et scripts
npm run lint
npm run lint:fix

# Échoue si CLAUDE.md a dérivé par rapport à l'arborescence qu'il décrit
npm run check:docs

# Test de fumée Playwright sur la vraie application Electron
npm run test:e2e
```

La CI lance trois jobs à chaque push et chaque PR : `lint` (rapide, échoue en premier),
`test` (Node 18 et 20 sur Windows, Linux et macOS) et `e2e` (Ubuntu sous `xvfb-run`).
Le job E2E est **bloquant** : il ouvre la vraie application, parcourt chaque onglet de
la barre latérale, et échoue à la moindre erreur console du renderer ou plantage du
processus principal.

`npm run test:e2e` est tenu hors de `npm test` parce qu'il lui faut un affichage et un
bundle renderer compilé. Le lancer en local demande aussi que les modules natifs soient
compilés pour l'ABI d'Electron (`npm run postinstall`).

pas de framework front : le renderer est bundlé par esbuild en ESM avec code splitting.

### Frontières

La séparation main/renderer est appliquée par ESLint, pas seulement par convention :

- Le renderer n'obtient jamais `child_process`, `fs`, `net` ni `electron` directement.
  Il parle au processus principal uniquement via `window.electron_api`.
  **`child_process` n'est délibérément jamais exposé** : le renderer affiche du markdown
  écrit par un modèle, donc un pont vers le lancement de processus transformerait
  n'importe quelle injection HTML en exécution de code.
- `contextIsolation: true` et `nodeIntegration: false` dans les cinq fenêtres.
- La CSP d'`index.html` n'a pas d'`'unsafe-inline'`, donc du HTML injecté dans le chat
  ne peut pas exécuter de script. Tout markdown rendu passe par `dompurify`.

Si une de ces règles se déclenche, le correctif est un nouveau handler IPC, pas un
`eslint-disable`.
